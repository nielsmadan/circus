# Circus

Circus is a Tauri 2 macOS desktop app for [ringleader](https://github.com/nielsmadan/ringleader) (`rl`). It has three tabs (Inbox, Archive, Harvests); only the Inbox is implemented: a Superhuman-style list and reading pane over dormant agent sessions, with one-key decisions, undo, a snooze dialog, a command palette and resume in iTerm2.

The app talks to ringleader only by spawning `rl inbox --json [--scan]`, `rl data export … --json`, the guarded `rl session archive|delete|harvest|snooze|keep|unkeep|mark reviewed … --json --if-mtime=…` and `rl handoff triage … [--dry-run --json]` (the real one runs in the terminal, like resume). Onboarding also runs `rl --version`, `rl data presence install --yes --json` and `rl install skills|hooks --yes`; these are not in ringleader's contract yet. Circus depends on the ringleader release pinned in `ringleader.json` (`minimum`, `latest`, wheel and its sha256): onboarding installs that wheel with `uv tool install` (and uv itself from the pinned `uv_version` installer, checked against `uv_installer_sha256`, with `UV_NO_MODIFY_PATH=1`), and the dev recipes fetch the same release. The contract is `docs/tech/json-contract.md` in the ringleader repo; that file is the source of truth. Read `docs/architecture.md` before changing the Rust/TS boundary, the outbox or the close gate, and `docs/development.md` for dev, QA and the performance procedure.

## Layout

- `src/` — React 19 + TypeScript frontend. `api/` (typed Tauri client, the only typed consumer of `rl` responses), `inbox/` (controller, outbox, batches, derive, the list selection in `marks.ts`, the sidebar's groupings in `sidebarGroups.ts`, views and their hooks), `setup/` (onboarding and the update banner), `snooze/`, `palette/`, `shortcuts/`, `dev/` (in-memory fake API for `pnpm dev:fake`, which mirrors the guarded `rl session` refusals and their order), `test/` (fixtures and golden copies).
- `src-tauri/` — Rust: `rl.rs` (typed requests, raw-bytes responses), `process.rs` (process groups, deadlines), `config.rs` (`rl` resolution, settings), `resume.rs`, `setup.rs` (manifest, install steps, `setup.json`), `close.rs` (close gate), `cache.rs` (list cache), `commands.rs` (and `commands/setup.rs`), `lib.rs` (menu, window events).
- `scripts/` — `sandbox-env.sh` (builds the synthetic world and exports its environment) and its test; `fetch-ringleader.sh` (stage the pinned release), `stage-ringleader.sh` (release-shaped assets from a checkout), `ringleader-venv.sh` (the venv both use).
- `Justfile` — every command below.

## Commands

- `just setup` — install dependencies and git hooks, then verify. `just doctor` — verify tools and checkout state.
- `just check` — everything CI runs: prettier, eslint, tsc, vitest (the `*.perf.test.ts*` budgets run in a second, serial pass), vite build, cargo fmt/clippy/test, the `sandbox-env.sh` test.
- `just test`, `just lint`, `just format`, `just typecheck`, `just build`.
- `just run` — the native app against the user's live sessions through the installed `rl`. Agents never run it.
- `just sandbox` — the native app against a freshly built synthetic world. `just test-smoke` — the Rust client against real `rl` in that world.
- `pnpm dev:fake` — Vite only, in-memory fake API, no Tauri and no `rl`. Agents drive this with agent-browser.
- `just build-debug` — unsigned `src-tauri/target/debug/bundle/macos/Circus.app`.
- `just sync-golden` / `just golden-check` — copy / compare the pinned release's `contract-golden.tar.gz` into `src/test/golden/`.
- `just pin-ringleader VERSION` — pin a ringleader release (version, wheel, sha256 from its `SHA256SUMS`); raise `minimum` by hand when circus starts needing it. `just stage-ringleader CHECKOUT` — build release-shaped assets from a checkout into `.cache/ringleader/checkout` for contract work before a release; point `CIRCUS_RINGLEADER_DIR` at it.

## Gotchas

- Agents never touch live data: `just run` is for the user only. Agents run `rl` only through `sandbox` and `test-smoke`, and only inside the world built by the release's `ringleader.devtools.gui_world`; `pnpm dev:fake` never spawns `rl`. `scripts/sandbox-env.sh` aborts unless every world variable lies under the world root. Never run the installed `rl` or `python -m ringleader` outside those recipes.
- In the sandbox the app refuses every decision unless the list's `registry` lies under `CIRCUS_WORLD_ROOT` (`decisionGuard` in `src/inbox/derive.ts`).
- Changing the contract: edit ringleader's `docs/tech/json-contract.md` and goldens and circus together; `just stage-ringleader` the checkout and run the recipes with `CIRCUS_RINGLEADER_DIR`, then, once ringleader is released, `just pin-ringleader` and `just sync-golden`. `just test-smoke` and `golden-check` fail on drift. Between those steps a key circus already reads but the pinned release lacks is listed in `UNRELEASED_LIST_KEYS` (`src/api/golden.test.ts`), and the smoke test runs only against the staged checkout, whose goldens fail `golden-check` until the pin moves; drop the entry when you pin and sync.
- Onboarding (`src/setup/`, `src-tauri/src/setup.rs`) is the only UI that names ringleader. It runs on first launch and whenever the installed `rl --version` is missing or below `minimum`; between `minimum` and `latest` an update is optional and, if the user agreed, offered by a banner. Answers live in `setup.json` next to `preferences.json`. Installing is refused in the sandbox.
- `rl` resolution order: `CIRCUS_RL` (shell-words), `rl_command` in `settings.json`, the path a Circus install recorded in `setup.json` (only an install writes it; page script cannot), one login-shell probe, then `~/.local/bin`, `/opt/homebrew/bin`, `/usr/local/bin`. With `CIRCUS_ENV_LABEL` set, an unset, empty or unsplittable `CIRCUS_RL` resolves to no `rl` at all, never to an installed one. Other variables: `CIRCUS_ENV_LABEL` (SANDBOX badge, guard on), `CIRCUS_WORLD_ROOT`, `CIRCUS_RESUME_DRY_RUN=1` (resume and the triage hand-off return the command instead of launching). `settings.json` (in the app config dir) keys: `rl_command` and `terminal_command`, both argv arrays; `{command}` inside any `terminal_command` element is replaced by the `rl resume …` or `rl handoff triage …` command line. When `CIRCUS_RL` or `settings.json` names the command, an install leaves it in place.
- `rl` JSON responses travel as raw bytes: Rust checks only `kind` and `version` through a minimal `Envelope` struct and returns stdout unchanged. Never add a `serde_json::Value` round-trip. `src/api/client.ts` decodes with one module-level `TextDecoder`.
- A new Tauri command needs three edits: the `#[tauri::command]`, its name in `src-tauri/build.rs`, and `allow-<name>` in `src-tauri/capabilities/default.json`. There is no shell plugin and no generic exec. Core permissions are listed one by one (today only `core:event:allow-listen` and `allow-unlisten`); never add `core:default` or any `core:menu:*`, which let page script install a menu whose Quit bypasses the close gate.
- Children of `rl` spawn with `setsid` (own session and process group). On a deadline circus sends SIGTERM to the group, waits `KILL_GRACE` (5 s, longer than ringleader's own 2 s model-kill grace), then SIGKILL. The login-shell probe is SIGKILLed at its 5 s deadline instead, because interactive shells ignore SIGTERM.
- Resume launchers inherit the resolved login PATH (`resume::WithPath`), so a custom `terminal_command` like `["wezterm", "start", "--", "sh", "-c", "{command}"]` resolves from a Finder-launched app. `{command}` is one shell command line, so a terminal that runs argv needs the `sh -c` wrapper. A custom launcher still running after 5 s (a terminal that stays in the foreground) counts as launched and is left running; it is never killed.
- The Quit menu item is custom because the predefined one bypasses the close gate. Dock › Quit and logout cannot be intercepted; unsent decisions are dropped then.
- `@shortcutkit/core`, `@shortcutkit/dom` and `@shortcutkit/react` use Git subdirectory dependencies pinned to the same full commit in `package.json`. `pnpm install --frozen-lockfile` fetches their sources; Vite aliases and TypeScript paths target the installed `src/index.ts` entries because this revision has no built `dist/`. Both doctor commands check those entries. Keep all three pins together when upgrading. `ShortcutKitProvider` owns input attachment; use the library hooks directly. Do not add matching, rebinding, legend or persistence code here.
- Recipes that compile (`lint`, `test`, `run`, `sandbox`, `test-smoke`, `build-debug`) depend on `ensure-dist`, because `generate_context!` needs `dist/`.
- Appearance is native: View › Appearance calls `AppHandle::set_theme` and the webview's `prefers-color-scheme` follows. Style both themes with Tailwind's default media `dark:` variant only; a new surface needs its `dark:` classes. `preferences.json` follows the sandbox rule of the list cache (`appearance::preferences_path`).
- Inbox behaviour that is deliberate: Undo shows only on the newest unsent decision's toast; decision toasts are not evicted by the 5-toast cap; a failed `exit()` cancels the Rust close gate (`close_cancel`) and reopens the outbox; the Finishing overlay states when Rust will quit regardless and how many unsent changes that would drop; changing split moves the cursor to the first row and clears the selection; windowed rows carry no `aria-setsize`/`aria-posinset` (an index prop would break the re-render budget); the reading pane shows an older tail labelled "May be out of date…" while a fresh one loads; the snooze dialog's last-focused input wins and the dialog unmounts on confirm.
- The `*.perf.test.ts*` budget tests are requirements. Never loosen, skip or retry them to get green. The key path (`j`/`k` to paint) stays free of `await`, timers, `startTransition`, `useDeferredValue` and layout reads.
- Exact-pin every npm dependency and Rust crate (no `^`, no `~`).

## Conventions

- User-facing text never mentions ringleader, `rl`, its commands or its skills: banners, toasts, errors, dialogs, menus, the palette, tooltips. If the user needs a ringleader action, circus gives them a button or command that runs it; never tell them to run something in a terminal. Name failures in circus's terms ("Couldn't load sessions"), with the raw detail behind a disclosure at most. The single exception is first-run setup, which may say once that circus installs ringleader.
- Commits: `feat:`, `fix:` or `chore:`, no scope, one short clause, no body. Message names only this repo's change.
- Comments: none by default; one terse line for a non-obvious invariant or workaround. No JSDoc.
- Functional style: pure functions at module boundaries, effects at the edges, no mutation of arguments.
- Tests assert what the code does, not what it does not do.
- `pnpm` 12.9.0 (`packageManager`), Node 24, TypeScript strict, prettier (`singleQuote`, `trailingComma: all`, `printWidth: 100`), Rust edition 2024 with clippy `-D warnings`.
